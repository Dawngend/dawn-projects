# Source Terms

Verified automated-use, feed, and API rules from official source pages (checked 2026-11-13).
This file records each source's published rules only and does not claim that this project complies with them.

## Himalayas

- **Endpoint:** `https://himalayas.app/jobs/api`
- **Official links:**
  - Remote Jobs API Reference: https://himalayas.app/docs/remote-jobs-api
  - Terms and Conditions (Clauses 30, 30A, 93, and Clause 113): https://himalayas.app/terms (API terms anchor: https://himalayas.app/terms#api)
- **API permission vs. site-scraping restrictions:** Clauses 30 and 93 of the Terms prohibit data mining, robots, crawlers, scripts, screen scraping, and other automated data gathering or extraction on the Himalayas website without prior written approval, and the API reference notes that HTML job pages are protected against automated traffic. Clause 30A states that Clauses 30 and 93 do not restrict use of the public API, job feeds, and MCP server when used in line with their published documentation and rate limits. Under Clause 113 and the API reference, personal and commercial API integrations are allowed without prior approval if they follow the API conditions below.
- **Attribution:** Clause 113(b) requires clearly identifying Himalayas as the source of the jobs with a visible link to the Himalayas job listing or to https://himalayas.app. The API reference states that any website or app displaying Himalayas job data must show visible Himalayas source credit and a visible link back to https://himalayas.app.
- **Apply links:** Clause 113(a) and the API reference require every Apply action for a Himalayas job to use the `applicationLink` field returned by the API, and prohibit replacing it with a direct employer or applicant tracking system (ATS) link.
- **Permitted display:** Clause 113(c) and the API reference allow displaying the jobs only on websites, job boards, or apps that you operate. Passing the jobs on to third parties (such as other job boards, aggregators, job search engines, Google Jobs, or LinkedIn Jobs, including via feeds or `JobPosting` structured data) is prohibited.
- **Rate limits and caching:** Clause 113(d) requires caching job data where possible and staying within request limits. According to the API reference, `/jobs/api` works without an API key, returns at most 20 jobs per page (`cursor` pagination preferred, `offset` deprecated), and refreshes its cached feed every 24 hours, so polling more than once per day adds no new data. Unkeyed `/jobs/api` requests share one public allowance across all callers (exact numeric cap not published; the single-job status endpoint allows 60 requests per minute without a key). A free API key allows 60 requests per minute and 10,000 requests per UTC day per account across all keys, and Clause 113(e) requires keeping any API key private on your own servers. Cached responses do not count against rate limits, and exceeding rate limits or IP abuse controls returns HTTP `429`.
- **Removing expired jobs:** Clause 113(d) requires removing jobs once they expire. Each job object includes `expiryDate` (Unix timestamp in seconds), and the API reference notes that jobs can close before `expiryDate` if an employer removes the posting. To drop closed or expired listings without requesting HTML job pages, the API reference instructs callers to re-read the feed daily and remove jobs no longer in it, or check `https://himalayas.app/jobs/api/companies/:company/jobs/:slug` (`200` if open, `410` if closed).

## Remote OK

- **Official references:** [FAQ answer on API and RSS/JSON feeds](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs) and [Terms of Service](https://remoteok.com/legal) (the Terms page says it was updated on 2026-10-26).
- **API/feed access:** Remote OK lists `https://remoteok.com/api` (JSON) and `https://remoteok.com/remote-jobs.rss` (RSS) as free public feeds that require no authentication. It documents tag filtering with `?tag=dev` or `?tags=dev,python`. [Source: FAQ feed answer](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs).
- **Reuse:** The FAQ explicitly addresses building a job aggregator or sharing the feed publicly, but does not state a general data license or separately define storage, redistribution, or commercial-reuse rights. [Source: FAQ feed answer](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs).
- **Attribution and link-back:** For a job aggregator or publicly shared feed, the FAQ asks for Remote OK credit and a link back to each original job post URL so candidates can apply directly. The Terms more broadly require a web or in-app hyperlink back to Remote OK on the page or app screen where data from its APIs or site is used. Sources: [FAQ feed answer](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs) and [Terms of Service](https://remoteok.com/legal).
- **Website scraping, separate from feed access:** The Terms apply to Remote OK's websites, apps, communities, and other properties, and state that copyright in them rests with Remote OK unless otherwise stated. Neither checked page grants a separate right to crawl or scrape HTML pages, nor publishes detailed crawler rules. This is not a finding that scraping is permitted. Sources: [Terms of Service](https://remoteok.com/legal) and [FAQ feed answer](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs).
- **Stated and unstated limits:** Beyond free, unauthenticated access, the FAQ specifies no numeric request-rate limit, polling interval, caching rule, or retention/removal rule for these feeds. The Terms do not guarantee constant website availability and disclaim liability for downtime or access failure beyond Remote OK's reasonable control. Sources: [FAQ feed answer](https://remoteok.com/faq#is-there-an-api-or-rssjson-feed-of-remote-jobs) and [Terms of Service](https://remoteok.com/legal).

## Remotive

- **Endpoint:** `https://remotive.com/api/remote-jobs`
- **Official links:**
  - Public API page: https://remotive.com/remote-jobs/api
  - Official API documentation (linked from the API page): https://github.com/remotive-com/remote-jobs-api
  - Terms of Use: https://remotive.com/terms-of-use (dated March 18, 2026 in Section 1; page footer states updated 07/10/2026)
- **API permission vs. website scraping restrictions:** Sections 7 and 8 of the [Terms of Use](https://remotive.com/terms-of-use) prohibit scraping, crawling, or using automated means to access `remotive.com` or extract data without written permission, prohibit copying or redistributing website job listings or company data to third parties, and prohibit using subscription listings commercially or to build a job-listing database. Separately, the [Public API page](https://remotive.com/remote-jobs/api) and linked [API documentation](https://github.com/remotive-com/remote-jobs-api) grant public `GET` access to `https://remotive.com/api/remote-jobs` so developers can share active Remotive jobs further under the API-specific conditions below. The website Terms of Use do not mention the public API or specify how website/subscription restrictions apply to non-display API storage.
- **Reuse and display:** Under the [Public API page](https://remotive.com/remote-jobs/api) (repeated in the [API documentation](https://github.com/remotive-com/remote-jobs-api)), API access is granted so developers can share Remotive jobs further, but callers must not submit Remotive jobs to third-party job sites or aggregators, including Jooble, Neuvoo, Google Jobs, and LinkedIn Jobs. Remotive notes on the same page that a private, paid API is available by contacting `hello@remotive.com`.
- **Attribution and canonical link-back:** Both the [Public API page](https://remotive.com/remote-jobs/api) and [API documentation](https://github.com/remotive-com/remote-jobs-api) require linking back to the canonical Remotive listing URL (`url` in the API payload) AND mentioning Remotive as the source so Remotive receives traffic from the listing, and warn that Remotive will terminate API access if either requirement is omitted.
- **24-hour delay:** Both the [Public API page](https://remotive.com/remote-jobs/api) and [API documentation](https://github.com/remotive-com/remote-jobs-api) state that jobs in the public API are delayed by 24 hours so listings are attributed to Remotive across platforms.
- **Email and signup restriction:** Both the [Public API page](https://remotive.com/remote-jobs/api) and [API documentation](https://github.com/remotive-com/remote-jobs-api) state that displaying Remotive jobs in order to collect signups or email addresses before showing a listing breaches Remotive's terms of service.
- **Stated and unstated API limits:** The [Public API page](https://remotive.com/remote-jobs/api) itself states no numeric rate limit, polling schedule, authentication requirement, caching rule, or retention/expired-job removal rule. The linked [API documentation](https://github.com/remotive-com/remote-jobs-api#request-rate-limiting) specifies unauthenticated `GET` access (with optional `category`, `company_name`, `search`, and `limit` parameters), advises polling at most 4 times per day, and states that requests exceeding 2 per minute are blocked. Although the documentation notes that the endpoint returns active listings only, neither official API page specifies a daily request quota, caching TTL, data-retention limit, deadline for deleting closed jobs, or rules for internal/offline analysis without public display.

## We Work Remotely (WWR)

- **Official links:**
  - Public RSS Feed page: https://weworkremotely.com/remote-job-rss-feed
  - General Terms and Conditions: https://weworkremotely.com/terms-and-conditions (updated October 23, 2026)
- **Permitted RSS use:** The [Public RSS Feed page](https://weworkremotely.com/remote-job-rss-feed) says that anyone can use its public RSS feed to fill a remote job feed with openings listed on WWR. It publishes `https://weworkremotely.com/remote-jobs.rss` for all jobs and separate category feeds listed on that page. This is feed-specific permission, not a statement that WWR's HTML pages may be scraped.
- **Attribution and link-back:** The [Public RSS Feed page](https://weworkremotely.com/remote-job-rss-feed) asks all feed users to attribute the links back to We Work Remotely. It does not specify exact attribution wording, placement, or markup.
- **Separate general site Terms:** The [General Terms and Conditions](https://weworkremotely.com/terms-and-conditions) apply to WWR's websites and other services, state that WWR or its licensors/providers own the service materials, and grant users a limited, non-transferable, non-sublicensable, non-exclusive, revocable right to access and use those materials subject to the Terms. They also allow WWR to suspend access immediately when it identifies an immediate security or operational risk. These general provisions do not publish separate HTML crawling/scraping permission or detailed crawler rules.
- **Unspecified RSS rules:** The [Public RSS Feed page](https://weworkremotely.com/remote-job-rss-feed) states no numeric request-rate limit, polling interval, authentication requirement, caching rule, storage/retention limit, or expired-job removal rule. It also does not separately define commercial reuse, redistribution beyond filling a job feed, or a general data license. Neither checked page clarifies how the general Terms' revocable materials license interacts with long-term storage of RSS data.

## Jobicy

- **Scraper endpoint vs. current official coverage:** `job_market_scraper/sources.py` requests `https://jobicy.com/api/v2/remote-jobs`. Jobicy's current official developer documentation and OpenAPI specification instead document `GET https://jobicy.com/api/jobs` (plus `GET https://jobicy.com/api/jobs/status`), MCP (`https://jobicy.com/mcp`), and RSS (`https://jobicy.com/jobs/feed`, with `https://jobicy.com/feed/job_feed` explicitly retained for RSS compatibility). None of the checked official pages mention `/api/v2/remote-jobs`, state whether that legacy path remains supported, or confirm that the permissions published for `/api/jobs` or the RSS feeds apply to `/api/v2/remote-jobs`. Permission for `/api/v2/remote-jobs` cannot be inferred from `/api/jobs` or from the RSS feeds.
- **Official links:**
  - Remote Jobs API & RSS Feed documentation (updated October 19, 2026): https://jobicy.com/jobs-rss-feed
  - OpenAPI 3.1 specification (`v2.2.19`): https://jobicy.com/api/openapi.json
  - Official API repository (linked from the API page): https://github.com/Jobicy/remote-jobs-api
  - Terms of Service (updated November 2026): https://jobicy.com/terms-and-conditions
- **Website scraping restrictions vs. official API carve-out:** In the [Terms of Service](https://jobicy.com/terms-and-conditions), `General Prohibited Conduct` (clause e) prohibits harvesting or scraping data *"other than via our official API under its terms,"* and `Copyright` prohibits copying, storing in a retrieval system, retransmitting, or redistributing website materials without prior written consent except as expressly provided. Because `/api/v2/remote-jobs` is omitted from the current API documentation and OpenAPI contract, the official pages do not confirm whether `/api/v2/remote-jobs` is covered by that official-API carve-out.
- **Documented permissions and reuse (stated for `/api/jobs`, unconfirmed for `/api/v2/remote-jobs`):** On the [API/RSS page](https://jobicy.com/jobs-rss-feed) (`#japi-fair-use` and `#japi-faq`), Jobicy allows unauthenticated `GET` use of `/api/jobs` without individual approval for personal and commercial products (including job boards, aggregators, SaaS apps, newsletters, internal dashboards, research tools, and AI analysis/derived outputs), while requiring direct contact only for high-volume commercial partnerships or custom data arrangements. Callers of the documented API may store, cache, process, redistribute, and retain job data and AI-derived outputs without a fixed retention limit, provided listings are synchronized regularly and confirmed closed or expired positions (checked via `GET /api/jobs/status`, since dropping out of the 7-day feed alone does not mean closure) are excluded from active listings or clearly marked unavailable in saved histories. Spam networks, misleading job databases, and abusive or harmful services are prohibited; receiving direct employer/ATS links in `url` requires a paid Bearer key via the [Commercial Jobs API](https://jobicy.com/api-dashboard) ($0.01 per new direct-link job per key).
- **Attribution and link-back (stated for documented public interfaces):** Under [Fair Use](https://jobicy.com/jobs-rss-feed#japi-fair-use), the [FAQ](https://jobicy.com/jobs-rss-feed#japi-faq), and the [OpenAPI specification](https://jobicy.com/api/openapi.json), public API users must clearly credit Jobicy as the original source when displaying listings, must not remove attribution or present listings as their own original postings, and must keep public `url` / Apply links directed to the canonical Jobicy job page (the site footer also states *"Use of content requires a clickable source link"*; commercial Bearer-key responses omit the attribution requirement per the OpenAPI commercial example).
- **Rate, polling, and unstated limits:** For the documented interfaces on [jobicy.com/jobs-rss-feed](https://jobicy.com/jobs-rss-feed) and [openapi.json](https://jobicy.com/api/openapi.json), `/api/jobs` serves a rolling 7-day publication window with a 3-hour upper publication delay (`count` documented as 1-100 default 100 on the web page and 1-200 default 200 in `openapi.json`, using 24-hour `nextCursor` pagination), automated API sync passes, `/api/jobs/status` batch checks, and RSS polling must each start no more than once per hour (sequential cursor pages within one sync pass are allowed), public `/api/jobs` responses may be cached up to 3,600 seconds (`private, no-store` for authorized commercial responses), and HTTP `429` responses require honoring `Retry-After` or exponential backoff. Neither official source publishes an exact numeric HTTP `429` request cap, and no checked official page specifies rate limits, window behavior, deprecation status, or reuse/attribution terms for `/api/v2/remote-jobs`.
